# Repository setup for maintainers

The GitHub repository intentionally begins as a documentation and issue tracker. Code integration is pending provenance review.

1. Review repository contents and rights of source code before adding any code.
2. Keep commercial game images/ELFs/BIOS and generated executables out of Git.
3. Work in branches and use pull requests for technical patches.
4. Attach measurement evidence to issues; update ROADMAP.md as tasks finish.
5. Before any public release, check dependency notices, third-party licenses, executable contents and clean-machine test evidence.
